# Torrent Hub — отдельный репозиторий Home Assistant OS

Личный поиск торрентов по интернет-трекерам. Объединяет встроенный **Prowlarr** (прямой поиск в интернете по выбранным трекерам) и опциональные внешние **JacRed/Knaben** API. Поддерживает HTTP/SOCKS5 через «Прокси от Бориса», регулярные проверки, получение magnet из .torrent и отправку на несколько TorrServer.

## Статус

**1.0.0-rc1 — кандидат на проверку.** Пройдены автоматические тесты логики и браузерного интерфейса. ARM64 контейнер ещё не собран и не проверен на реальном Raspberry Pi. Не выдавайте RC за подтверждённый production release.

## Установка

1. Создайте **отдельный** пустой GitHub-репозиторий (например `barawkaa/torrent-hub-ha`). Выложите в корень содержимое данного архива, исправив адрес в `repository.yaml`.
2. Подключите URL нового репозитория в Home Assistant OS → Настройки → Приложения → Магазин → Репозитории.
3. Старое приложение Torrent Hub 0.1.0 в репозитории `proxy-ot-borisa` не обновляйте. Чтобы избежать конфликта идентичных slug, сначала сделайте резервную копию HA, затем удалите старое приложение и подключите новый репозиторий. «Прокси от Бориса» при этом не меняется.
4. Установите Torrent Hub из отдельного репозитория. Первая сборка может быть долгой, поскольку включает Prowlarr ARM64 и .NET.
5. Откройте Torrent Hub в HA. На странице **Прокси** укажите правильный логин/пароль SOCKS5, нажмите «Проверить введённые данные», затем «Сохранить и применить к поисковику».
6. На странице **Трекеры** добавьте несколько индексаторов из каталога Prowlarr. Для приватных трекеров укажите учётные данные. Первый успешный тест может требовать изменения адреса трекера или прокси.
7. На странице **Диагностика** нажмите «Проверить всё». Убедитесь в доступности прокси, движка и обоих TorrServer.
8. Выполните поисковый запрос, скопируйте magnet или выберите TorrServer и отправьте раздачу.

## Прокси и отсутствие скрытого обхода

- **Только через прокси:** поиск JacRed/Knaben не переключается на прямой доступ. Для Prowlarr применяется глобальная конфигурация прокси через его локальный API. До её успешного применения поиск Prowlarr блокируется с ошибкой, а не идёт напрямую.
- **Напрямую:** указанный локальный Prowlarr и JacRed/Knaben работают без прокси, если этот режим успешно применён.
- **Автоматически:** только внешние API умеют переключаться с прямого доступа на прокси. Prowlarr этот режим не поддерживает: поисковый запрос завершится диагностикой, предлагающей выбрать фиксированный маршрут.
- **TorrServer** в локальной сети **всегда напрямую**, прокси не используется.
- Prowlarr может выполнять служебные запросы отдельно от поисковых. Полная сетевая блокировка всех прямых исходящих соединений самого Prowlarr потребует дополнительной фильтрации на уровне сети; режим приложения гарантирует блокировку **поиска через Torrent Hub**, а не все исходящие соединения бинарника.

## Состав

- `torrent-hub/app/main.py` — API, мониторинг, конфигурация, интеграция Prowlarr и TorrServer.
- `torrent-hub/app/core.py` — маршрутизация, magnet, bencode, дедупликация результатов.
- `torrent-hub/app/runner.py` — запуск и контроль Prowlarr и API.
- `torrent-hub/app/static/index.html` — интерфейс HA Ingress без внешних JavaScript/CDN.
- `tests/` — автоматические проверки.
- `.github/workflows/verify.yml` — тесты и ARM64 Docker build на GitHub Actions.

## Безопасность

- Web UI доступен через Home Assistant Ingress и авторизацию HA. Не пробрасывайте порт API в интернет.
- Порт 9696/tcp для прямого входа в Prowlarr по умолчанию закрыт; открывайте только при необходимости на защищённой локальной сети.
- Пароли прокси и TorrServer хранятся в `/data/torrent-hub/state.json` (права 0600) и не возвращаются в ответе `/api/config`.
- Получение torrent-файла выполняется только для результатов, полученных в поиске, по временному ID. Произвольный URL для загрузки клиент не может отправить напрямую.
- Ручные проверки используют несохранённые поля формы, но не перезаписывают их.

## Что осталось подтвердить на реальном железе

Запуск Prowlarr из ARM64 multi-stage Docker-образа, настройку индексаторов разных типов, реальные ответы пользовательских источников, сетевую доступность через SOCKS5 с аутентификацией и сохранение данных после перезапуска HA OS. Без этого нельзя честно утверждать, что приложение готово к коммерческому использованию.
