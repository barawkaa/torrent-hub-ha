# Torrent Hub — домашний метапоисковик для Home Assistant OS

![Torrent Hub logo](torrent-hub/icon.png)

**Torrent Hub** — самостоятельный Home Assistant OS add-on для поиска BitTorrent-раздач через интернет. Поисковый движок Prowlarr работает внутри того же контейнера. Отдельная установка Prowlarr, Jackett или JacRed не требуется. К источникам можно подключать собственные HTTP/SOCKS5-прокси, в том числе с авторизацией. Через Ingress интерфейс доступен с компьютера и телефона, включая удалённый доступ через настроенный Home Assistant.

## Возможности

- Поиск сразу во **всех включённых источниках**, без обязательного публичного агрегатора. Используются прямые интернет-трекеры (через встроенный Prowlarr) и подключаемые API JacRed, Knaben, Torznab.
- **RuTor, NoNaMe Club (NNM-Club), MegaPeer, Kinozal, Rustorka**: их определения включаются в образ на этапе сборки; при первом старте приложение пытается автоматически добавить публичные RuTor, NNM-Club и MegaPeer. Требующие авторизации источники добавляются с учётными данными через интерфейс. RuTracker также доступен при наличии подходящего определения в Prowlarr.
- При поиске выводится прогресс каждого источника: работает, найдено N результатов, пустой ответ или ошибка, время отклика. Результаты появляются по мере получения; не нужно ждать последнего медленного сервиса.
- Фильтры по качеству, сортировка по сидам, размеру, дате публикации, качеству и релевантности. Дубликаты по infohash объединяются.
- Режим **Расширенный поиск** позволяет выбрать источники и подключённые трекеры. Дополнительные поисковые API могут быть добавлены самостоятельно: тип + URL + при необходимости API-ключ.
- Отдельные действия **Копировать magnet** и **Отправить на TorrServer**. При отсутствии magnet система пробует получить infohash из `.torrent`.
- Подключение нескольких TorrServer, их мониторинг, просмотр библиотек и удаление раздач. По умолчанию внесены `192.168.1.148:8090` и `192.168.1.100:8090`.
- Периодические и ручные проверки прокси, Prowlarr, TorrServer, поисковых API; журнал ошибок. Проверка несохранённых полей не сбрасывает их значения.
- Параметры и пароли сохраняются на диске в разделе данных add-on; допускается резервное копирование и откат стандартными средствами HA OS.

## Установка

1. В Home Assistant OS откройте **Настройки → Приложения → Магазин приложений → ⋮ → Репозитории**.
2. Добавьте `https://github.com/barawkaa/torrent-hub-ha`.
3. Обновите магазин, установите или обновите **Torrent Hub**. Начиная с версии **1.1.3** приложение скачивает заранее собранный образ `ghcr.io/barawkaa/torrent-hub-ha:1.1.3` — Raspberry Pi **не собирает** контейнер и не скачивает его зависимости на этапе установки. Нужен доступ Home Assistant OS к `ghcr.io`.
4. Откройте приложение из боковой панели и на вкладке **Прокси** укажите свой HTTP/SOCKS5-сервер, логин и пароль или выберите прямой доступ. Кнопка «Проверить» не сохраняет поля; затем нажмите «Сохранить и применить».
5. Проверьте вкладку **Трекеры** (RuTor, NNM-Club, MegaPeer появляются автоматически, если создание прошло успешно), затем **Диагностика**. При необходимости добавьте RuTracker/Kinozal и сохраните учётные данные.
6. На вкладке **Поиск** введите фильм, ознакомьтесь с ходом поиска и отправьте найденную раздачу на один или несколько TorrServer либо скопируйте magnet.

**Миграция:** прежний Torrent Hub 0.1.0 был отдельным add-on в репозитории `proxy-ot-borisa`; его файлы из старого GitHub-репозитория удалены. Приложение «Прокси от Бориса» не удаляйте. Данные предыдущего Torrent Hub не импортируются автоматически, а ранее созданные TorrServer и прокси можно сохранить вручную. Сделайте резервную копию HA перед заменой add-on.

## Независимость и блокировки

Во время **работы** приложение не требует сервера разработчика или обязательного публичного поисковика. Прямой поиск через Prowlarr остаётся доступен независимо от JacRed. Пять определений трекеров уже включены в устанавливаемый образ. Сведения о новых раздачах требуют доступа хотя бы к одному трекеру/поисковому API либо к заранее полученным данным; гарантировать поиск при блокировке *всех* сетей технически невозможно.

Прокси не привязан ни к какому конкретному продукту. В режиме «Только через прокси» запросы Torrent Hub к внешним поисковым API не переходят напрямую, а перед поиском Prowlarr проверяется его прокси-конфигурация. Встроенный Prowlarr может делать собственные служебные запросы обновления определений; это ограничение отдельного движка, а не гарантия полного firewall-блокирования всех его соединений. Для полной сетевой изоляции потребуется дополнительная фильтрация на уровне сети. Запросы TorrServer идут напрямую через домашнюю сеть.

## Что проверяется автоматически

`pytest` проверяет сетевые маршруты, настройки, API-адаптеры, magnet, парсинг `.torrent`, работу прогрессивного поиска, сохранение секретов и операции с TorrServer. CI собирает контейнер `linux/arm64` и запускает его на нативном ARM64 GitHub runner; затем проверяет запуск Prowlarr, наличие пяти включённых определений и создание хотя бы одного публичного индексатора. Запуск только веб-панели без работающего поискового движка **не считается** успешным тестом.

**Границы тестирования:** CI не видит домашнюю сеть пользователя и не может гарантировать доступ к RuTor/RuTracker/NNM-Club из конкретного российского провайдера или исправность учётных данных прокси. Это подтверждается в разделе «Диагностика» после установки. Ни один конкретный трекер не гарантирует наличие каждого фильма.
