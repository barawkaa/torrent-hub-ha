# Torrent Hub 3.4.0 — самостоятельный поиск для Home Assistant и Android

Torrent Hub — веб-приложение для Home Assistant OS на Raspberry Pi 4 (aarch64). Поиск выполняется непосредственно на трекерах, без Prowlarr, чужого JacRed и локальной торрент-базы. Публичные агрегаторы JacRed, Knaben и пользовательские Torznab API подключаются дополнительно.

## Установка и обновление

1. В Home Assistant откройте **Настройки → Приложения → Магазин приложений → ⋮ → Репозитории**.
2. Добавьте `https://github.com/barawkaa/torrent-hub-ha`, если он ещё не добавлен.
3. Обновите каталог и установите или обновите **Torrent Hub** до версии **3.4.0**.
4. Дождитесь запуска и откройте веб-интерфейс из боковой панели HA.

Сборка **не выполняется на Raspberry Pi**: Supervisor скачивает предварительно проверенный ARM64-образ `ghcr.io/barawkaa/torrent-hub-ha:3.4.0`. Для скачивания нужен доступ HA OS к `ghcr.io`. При обновлении сохраняются настройки, доступные в `/data/torrent-hub`, включая прокси, источники и TorrServer. На всякий случай перед обновлением рекомендуется создать резервную копию приложения средствами Home Assistant.

## Как пользоваться

**Поиск:** название → поиск во всех включённых прямых трекерах и дополнительных агрегаторах → выдача с количеством раздающих, размером, датой и сортировкой. Агрегаторы подключаются одной общей галочкой; после поиска доступны уточняющие фильтры по найденным данным.

**Умный поиск:** отдельная вкладка с ползунками минимального/максимального размера и количества раздающих, приоритетом качества и сохраняемыми настройками. При гибком режиме раздачи за пределами предпочтений остаются в списке как альтернативы. Кнопка **«Подобрать лучший вариант»** использует результаты обычного поиска, если они уже доступны.

**Трекеры:** RuTor, NNM-Club, MegaPeer работают без обязательного аккаунта. RuTracker и Kinozal доступны во вкладке «Трекеры»: введи логин и пароль **от соответствующего сайта** и нажми «Подключить аккаунт». Torrent Hub отправит стандартную форму входа трекера и проверит авторизацию. При успешном входе включит источник и автоматически будет обновлять сессию для поиска и скачивания `.torrent`. Ручное копирование Cookie и настройки CSS не нужны. При капче/Cloudflare будет показана причина, поскольку автоматическое прохождение таких проверок не поддерживается. Можно менять зеркала, сетевой маршрут, включать источники и тестировать отдельные запросы.

**Свой трекер:** на вкладке «Трекеры» → «Добавить трекер» укажите адрес, шаблон поиска с `{query}`, CSS-селекторы результатов, названия, magnet и прочих метаданных. Подход предназначен для HTML-сайтов с простым поиском; сложные сайты с JavaScript, капчей или многоэтапной авторизацией потребуют специального адаптера.

**TorrServer:** введите серверы вручную, затем на карточке результата нажмите «Отправить» и выберите устройство; также доступны копирование magnet и скачивание исходного `.torrent` (если трекер его предоставляет). Можно сохранить исходный файл в браузер или `/media/TorrentHub` на HA.

**Прокси:** произвольный SOCKS5/HTTP, без зависимости от приложения «Прокси от Бориса». Маршруты настраиваются для каждого источника. В режиме только через прокси прямой обход не допускается.

**Диагностика:** группы «Система и сеть», «Трекеры», «Агрегаторы», «TorrServer»; проверка доступа и времени ответа. Кеш результатов хранится только в оперативной памяти (по умолчанию 10 минут, 350 записей), автоочищается и доступен для ручной очистки. Устаревший раздел Prowlarr удалён из интерфейса; при обновлении пользовательские данные не удаляются.

## Отдельный веб-интерфейс в локальной сети и Android

Torrent Hub автоматически открывает дополнительный веб-интерфейс по порту **8766**. **Логин, пароль и регистрация не нужны**: доступ к главной странице, поиску, настройкам и TorrServer открыт для устройств, которые могут подключиться к этому порту.

- Home Assistant: обычная боковая панель и штатный Ingress (порт 8765).
- Компьютер или телефон в домашней сети: `http://192.168.1.100:8766`, замените адрес на IP своей установки.
- Android: тот же веб-интерфейс в Chrome; для полноценной установки PWA нужен HTTPS-домен или иной защищённый контекст браузера.

**Важно:** интерфейс полностью открыт, включая изменение настроек, прокси и управление TorrServer. Если настроить на Keenetic общедоступное перенаправление порта или домен из интернета, **любой человек с доступом к адресу сможет управлять Torrent Hub без входа**. Поэтому не публикуйте порт 8766 в открытый интернет. Для удалённого доступа используйте VPN (например, Tailscale или Keenetic VPN), закрытую сеть или отдельную авторизацию на уровне роутера.

В версии 3.1.0 удалены прежняя форма входа, раздел «Доступ» и обработка учётных данных Torrent Hub; уже сохранённые данные входа не используются. Пароли прокси, TorrServer и Cookie трекеров — отдельные настройки, они не затрагиваются.

## Подключение RuTracker и Kinozal за две минуты

1. На вкладке «Трекеры» найди RuTracker.
2. Введи имя пользователя и пароль **от RuTracker**.
3. Нажми «Подключить аккаунт» — после подтверждённого входа источник включится и данные сохранятся.
4. Повтори для Kinozal с **его отдельными** логином и паролем.
5. Нажми «Проверить» на каждом трекере, затем выполни обычный поиск без агрегаторов.

Если сайт запросил капчу или проверку Cloudflare, приложение покажет понятную причину отказа. Без действующих учётных записей обеих площадок проверить успешную авторизацию удалённо невозможно.

**Хранение секретов:** логины и пароли трекеров находятся в файле настроек внутри личного HA add-on `/data/torrent-hub/state.json` с правами `0600`; API и UI возвращают только отметку о наличии сохранённого пароля. Сессионные Cookie после входа кэшируются только в оперативной памяти. Отдельный веб-порт `8766` открыт без авторизации согласно локальному режиму — любой клиент этой сети имеет доступ к настройкам, поэтому не публикуй его в интернет.

## Проверки релиза

Проверены Python-тесты, взаимодействия веб-интерфейса, нативная сборка ARM64, запуск контейнера с двумя веб-портами, открытый без пароля локальный интерфейс на порту 8766 и защиту от межсайтовых запросов, прямая поисковая выдача и magnet, отсутствие постоянной торрент-базы, работа временного кеша и анонимное скачивание образа из GHCR.

Что остаётся проверять в домашней сети: доступность каждого трекера через выбранный прокси, реальный вход в RuTracker/Kinozal со своими учётными записями, работа локального адреса и Keenetic на конкретном роутере и отправка файлов в физический TorrServer. Внешние сайты и блокировки не могут гарантировать 100% доступности.


## Новые источники версии 3.4.0

Во вкладке «Агрегаторы» появились **TorAPI**, **Torlock (Torznab)** и **JacRed.su**. Они по умолчанию отключены, чтобы непроверенное соединение не тормозило обычный поиск. Для использования: выбрать маршрут, нажать «Проверить поля», сохранить и включить успешный источник. Подключение публичных сайтов с Home Assistant может отличаться от доступности из GitHub Actions.

TorAPI `https://torapi.vercel.app` выполняет общий запрос к RuTracker, Kinozal, RuTor и NNM-Club; для раздачи без infohash при нажатии «Отправить» выполняется запрос ID к TorAPI и извлекается magnet. Прямой .torrent при необходимости логина трекера не скачивается. Документация: https://github.com/Lifailon/TorAPI/blob/main/docs.md.
Torlock использует `https://www.torlock.com/torznab/api` (без обязательного API-ключа). Документация: https://www.torlock2.com/apis.html.
JacRed.su: `https://jacred.su`. Наличие работающего сайта не гарантирует, что API доступен именно с твоего IP. Не обещается обход ограничений Cloudflare.
