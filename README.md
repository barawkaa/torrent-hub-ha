# Torrent Hub 3.0 — самостоятельный поиск для Home Assistant OS и Android

**Torrent Hub** выполняет прямой поиск торрент-раздач в интернете, без Prowlarr, внешней поисковой службы или собственной файловой базы. Внешние агрегаторы можно использовать дополнительно. Приложение предназначено для Home Assistant OS на ARM64 (включая Raspberry Pi 4).

## Основные возможности

- **Обычный поиск:** параллельный поиск по активным трекерам и, при включении, внешним агрегаторам. Выдача с числом раздающих, размером, датой публикации, сортировкой, magnet, скачиванием оригинального .torrent (когда сайт его предоставляет) и отправкой на любой сохранённый TorrServer.
- **Расширенный поиск:** выбор конкретных источников, качества и дополнительных параметров.
- **Умный поиск:** отдельная вкладка, ползунки минимального/максимального размера и количества сидов, качество, профили предпочтений. Близкие по размеру раздачи не скрываются, если не включён строгий фильтр. Кнопка «Подобрать лучший вариант» повторно использует результаты обычного поиска, пока они актуальны.
- **Прямые трекеры:** RuTor, MegaPeer и NNM-Club включены по умолчанию; RuTracker и Kinozal представлены как необязательные адаптеры с Cookie-авторизацией и по умолчанию выключены. Для них не проведены испытания с реальным пользовательским аккаунтом.
- **Собственные источники:** CSS-адаптер с URL, шаблоном поиска, селекторами названия, magnet, .torrent, сидов, размера, даты. Сложные формы авторизации могут требовать отдельного кода, одного адреса недостаточно.
- **Дополнительные агрегаторы:** JacRed, Knaben, совместимые Torznab API. Они не обязательны для самостоятельного поиска.
- **Прокси:** HTTP / SOCKS5 с логином и паролем, маршрут по источнику и проверки доступности.
- **TorrServer:** несколько устройств и выбор адресата в один клик.
- **Кеш:** только в оперативной памяти, по умолчанию 10 минут. Автоочистка, предел количества результатов, показ объёма, кнопка очистки. Поисковой базы на диске нет.
- **Диагностика:** отдельные группы для системы/сети, трекеров, агрегаторов и TorrServer.
- **Мобильный доступ:** адаптивный интерфейс/PWA через отдельный защищённый веб-порт.

## Установка / обновление

1. В Home Assistant OS добавьте репозиторий приложений: `https://github.com/barawkaa/torrent-hub-ha`.
2. В магазине приложений обновите каталог и установите или обновите **Torrent Hub** до **3.0.0**.
3. **До обновления сделайте резервную копию приложения.** При обычном обновлении настройки сохраняются, однако отдельные браузеры и версии HA следует проверить на месте.
4. Образ `ghcr.io/barawkaa/torrent-hub-ha:3.0.0` **уже собран и проверен для ARM64**. Raspberry Pi скачивает образ; не компилирует Prowlarr или Python-зависимости.

### Home Assistant Ingress

Открывайте Torrent Hub в боковой панели HA. Порт `8765` остаётся внутренним и обслуживает Ingress. **Не публикуйте порт 8765** через Keenetic: он рассчитан на авторизацию Home Assistant и не содержит собственного экрана входа.

### Отдельный адрес для Keenetic и Android

1. Откройте вкладку **Доступ** в Torrent Hub *через Home Assistant*.
2. Укажите логин и отдельный пароль (не короче 12 символов), сохраните.
3. В локальной сети откройте `http://<IP_HA>:8766` — должна появиться страница входа, поиск без авторизации недоступен.
4. В Keenetic привяжите свой домен к `<IP_HA>:8766` с **HTTPS-снаружи** и действующим сертификатом. Точный способ зависит от режима HTTPS-прокси Keenetic. Не открывайте публичный незашифрованный HTTP.
5. На Android откройте свой HTTPS-адрес через Chrome, выберите **«Установить приложение»** или **«Добавить на главный экран»**. Поиск будет работать на сервере HA; отдельная копия движка на Android не нужна.

При смене пароля существующие сессии внешнего доступа отзываются. Порт 8766 без заданного пароля не допускает работу с API. Пароль входа хранится в виде хеша; Cookies внешних трекеров — в защищённом файле настроек приложения. Не делитесь своими Cookies.

## Проверенный выпуск

[Контрольная проверка 3.0.0](https://github.com/barawkaa/torrent-hub-ha/actions/runs/39408579732) подтвердила тесты Python и мобильного DOM-интерфейса, сборку/запуск ARM64, отказ в доступе к API на порту 8766 без входа, запросы к реальным трекерам без сторонних агрегаторов, выдачу magnet, очистку RAM-кеша и анонимное скачивание образа из GHCR.

Эта проверка **не эквивалентна** испытанию на конкретном Raspberry Pi с домашним SOCKS5, реальной учётной записью RuTracker/Kinozal, телефоном или Keenetic. Доступность отдельных трекеров меняется, блокировки возможны. При сбое конкретного источника остальные работают независимо.
